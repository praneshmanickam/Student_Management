Student Record Management System Using B-Tree

A full-stack college project — the index is a hand written B-Tree in C, the interface is plain HTML, CSS and JavaScript.

Description

This project demonstrates the practical application of the B-Tree data structure for efficient student record management. The Register Number is used as the primary key, and the system supports insertion, searching, updating, deletion, traversal, and B-Tree visualization. Records are stored in students.dat and are re-indexed into the B-Tree every time the server starts.

How the website talks to the C B-Tree

/* every click in the browser becomes a C function call */ ADD student → POST /api/student → btree_insert() SEARCH student → GET /api/student?regNo=106 → search() UPDATE student → PUT /api/student?regNo=106 → btree_update() DELETE student → DELETE /api/student?regNo=106 → btree_delete() LIST students → GET /api/students → btree_traverse() TREE drawing → GET /api/btree → btree_to_json() STATS cards → GET /api/stats → height / node count

The B-Tree used in this project

Minimum degree T = 3 · maximum 5 keys per node · maximum 6 children per node

Invariants that are always maintained

  • Keys inside a node are kept sorted.
  • Every node (except the root) holds at least T − 1 = 2 keys.
  • Every node holds at most 2T − 1 = 5 keys.
  • An internal node with n keys has n + 1 children.
  • All leaves are at exactly the same depth — the tree is balanced.
  • The Register Number is the key used for ordering, search, insert and delete.

Operations implemented in C

createNode() allocate a node search() find a register number splitChild() split a full node insertNonFull() descend + insert insert() public insert deleteKey() public delete merge() merge two nodes borrowFromPrevious() rotate from left sibling borrowFromNext() rotate from right sibling fill() top up a node before descending traverse() in-order walk (sorted list) displayTree() console dump

Project structure

B-Tree logic, HTTP server logic and the frontend are kept in separate modules.

Student_BTree_Web/ ├── backend/ │ ├── main.c // entry point + JSON API routes │ ├── btree.c / .h // the B-Tree data structure (T = 3) │ ├── student.c / .h // student record + validation │ ├── storage.c / .h // students.dat load / save │ ├── server.c / .h // HTTP server (sockets + threads) │ └── students.dat // persistent records ├── frontend/ │ ├── index.html // dashboard + add + search │ ├── students.html // records table, edit, delete │ ├── btree.html // B-Tree visualization │ ├── about.html // this page │ ├── css/style.css │ └── js/{app,students,btree}.js ├── test/btree_test.c // invariant + stress test ├── Makefile ├── run.bat └── README.md

Future enhancements

Ideas that would extend the project

  • Range queries on Register Number using the ordered leaves of the B-Tree.
  • Animated step-by-step playback of a split, borrow or merge.
  • Department-wise secondary index and CGPA ranking reports.
  • Binary serialisation of students.dat for larger data sets.
  • Authentication and an admin audit log of every B-Tree operation.
  • Pagination and lazy loading for very large record sets.
